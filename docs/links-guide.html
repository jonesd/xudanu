Xudanu Links Guide

How to make the most of the most expressive link system ever shipped — when to use multi-ended connections, how to gather passages, and how to keep your documents readable.

1. The Mental Model: Sentences with Blanks

Forget everything you know about web links. A web link says "click here to go there" — one-way, one-ended, breaks when content moves, carries no meaning.

An Xudanu link is a sentence with blanks:

A link is a sentence: the type is the verb, each end fills one blank.

Five types, five verbs: Comment (annotates), Reference (points to), Disagreement (contests), Quotation (cites), See Also (relates). The type determines how the connection renders and what it means when you follow it.

2. The Simple Link (Where Everyone Starts)

The two-ended link is the fast path — select text, click Link, choose a type. This is 80% of what you'll do. It's deliberately the easiest gesture in the editor.

When to use a simple link
  • "This passage cites that source" (Quotation)
  • "This section is annotated by this comment" (Comment)
  • "See this related document" (See Also)
When NOT to use a simple link
  • When you need to connect MORE than two places → multi-ended (§3)
  • When multiple passages form ONE side of an argument → gather (§4)

3. Multi-Ended Links: When and Why

A link can have any number of ends. A three-ended link is not a chain (A → B → C) and not a list — it's one claim involving several places simultaneously.

A three-ended "Compare" link. Each end is a seat in the relationship, not a step in a chain.

When to use multi-ended links

Use multi-ended when...Example
You're making a comparison"Compare these three translations of the same passage"
You're triangulating"This claim, that evidence, and this counter-example"
You're showing a relationship among peers"These three documents all address the same question"

When NOT to use multi-ended

Don't use multi-ended when...Use instead
Two of the ends have different roles in the claimTwo separate links with different types
You're connecting more than ~4 places (visual density)A trail, or several focused links
It's really just a list of "see also"sMultiple See Also links (simpler to read)
The multi-ended trap: don't make every connection multi-ended just because you can. A three-ended link says "these places are in ONE relationship" — make sure that's what you mean. Three separate links say "these are three separate relationships." The distinction matters.

4. Gathering Passages into One End

The step change: a single END can hold multiple passages. This is gathering — several passages jointly filling one blank in the link's sentence.

A gathered end: three passages jointly filling one blank in a Disagreement link.

When to gather

Gather when...Why
Multiple passages jointly support one claim"These three data points together prove the thesis"
Passages are evidence for the same argument"These five quotes all show the same pattern"
You want the connection to be one claim, not fiveDeleting the link removes one argument, not five separate ones

When NOT to gather

Don't gather when...Use instead
Passages are sequential (part A then part B)A trail or separate links
Each passage supports a different sub-argumentSeparate links with the same type
Passages come from different roles in the debateMulti-ended link (different seats)
The test: can you describe the connection as "[all these passages] [verb] [that]"? If the sentence reads naturally, gather. If you need "and then" or "also separately", don't.

5. Links About Links

Any connection can itself be connected to. A comment on a link is a link whose end attaches to the link — a link about a link. This is how you argue about the argument.

Example: commenting on a disagreement
Original link:  "report §3" [disagrees with] "review §1"

Comment link:   "my analysis" [comments on] (the disagreement link)
                → the analysis addresses the CONNECTION itself,
                  not either end

Use this when the relationship is what you want to discuss, not the passages it connects. "This disagreement turns on a measurement difference" is a comment on the link, not on either document.

6. Layout: Keeping Dense Connections Readable

Dense links are the honest representation of a connected document. But readable requires effort. Here's what we've learned:

Principles

PrincipleWhat it means
One concept per viewWhen a page feels dense, hover one link — solo/focus mode quiets everything else
Colour = link identityAll passages of one gathered end share one colour; the i/N chips count the set
Compare, don't pileFor multi-ended links, use the comparison view (⇄) rather than trying to read all ends inline
Connections panel is the legendWhen the canvas overwhelms, the right panel lists every connection with type, end count, and actions

Practical tips

  • Start simple, gather later. Create a two-ended link first; gather additional passages into an end when you're sure they belong together.
  • Use named ends for clarity. "Evidence", "Context", "Counter-example" — names make multi-ended links readable in the panel.
  • Don't gather passages just because they're from the same document. Gather because they fill the same blank.
  • One gathered end per argument. If you have three arguments, make three links — not one link with three gathered ends.
  • Respect the colour coding. When all members of a gathered end share one colour, the visual grouping IS the information.

7. Common Mistakes

MistakeWhy it hurtsDo instead
Everything is multi-endedReduces signal; makes the panel noisyUse two-ended unless the claim genuinely involves 3+ peers
Gathering sequential passagesGathering means "jointly fill one blank", not "read these in order"Use a trail for sequences
Link spam (many low-value links)Dilutes the meaningful connectionsLink only when the relationship matters
Wrong type for the relationship"Disagreement" and "See Also" render and behave differentlyPick the verb that matches your intent
Gathering from different rolesGathering means "jointly", not "also"Use multi-ended (different seats) or separate links
Not naming multi-ended ends"End 3" is meaningless; "Context" teachesName ends for their role in the relationship

9. Recipes

Recipe: The three-way comparison

1. Select the first passage → Link → "Compare"
2. In the wizard's final step, use "Additional ends"
3. Select the second and third documents as targets
4. Name the ends: "Original", "Translation A", "Translation B"
5. Use ⇄ to see all three side by side

Recipe: The gathered evidence

1. Select your thesis passage → Link → "Disagreement"
2. Link to the opposing claim
3. Select each supporting passage in your document
4. Click Gather (green button) → choose the end
5. Watch the chips count up: 2/3, 3/3, 4/3...

Recipe: The connection critique

1. Find the link you want to comment on (Links panel)
2. Click the ⌗ button on its row
3. Write your analysis of the CONNECTION
4. Your comment becomes a link about the link

Recipe: The annotated reading path

1. Create a trail for the reading order
2. Add documents as stops
3. Within each document, create Comment links
   on passages that need explanation
4. The trail carries the structure; the links
   carry the commentary
