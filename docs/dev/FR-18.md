# FR-18: Workspace — A Unified Reading, Writing, and Exploration Surface

> A single page where you can explore the docuverse, read a document,
> write into it, and update its connections to the wider web of ideas.
> Replaces the current split between "AppShell (editing)" and per-feature
> panels (Perspective, Compare, Compound, Merge) with one coherent
> composable surface.

## Goal

Xudanu currently has a capable but scattered UI: editing lives in
`AppShell`, perspective comparison in `PerspectiveView`, compound
assembly in `CompoundBuilder`, merging in `MergePanel`, attribution in
`AttributionPanel`, document mapping in `DocumentMapPanel`. Each is good
in isolation but the user has to know they exist and how to reach them.

FR-18 unifies these into a **single workspace** with three guiding
principles:

1. **One page, many lenses.** The document is the center; everything
   around it is a swapable lens (graph, outline, provenance, reuse,
   timeline, diff). Toggling a lens doesn't navigate away.
2. **Read and write on the same surface.** There is no "edit mode" that
   takes you to a different page. You're always looking at the document;
   editability is a property of your access, not a different screen.
3. **Connection is the primary verb.** Every visible object is
   connectable. Every connection is explorable inline.

## Design Philosophy

### What makes this Xanadu (not Notion, Roam, Obsidian)

| Tool | Core unit | Link model | Transclusion | Provenance |
|---|---|---|---|---|
| Notion | Block | Reference, not bidirectional | Embed (copy) | None |
| Roam | Block | Bidirectional `[[wiki]]` | Block embed | None |
| Obsidian | File | Bidirectional wiki + graph | Block ref | Plugin |
| OpenXanadu | Byte range | Unbreakable, typed | First-class | Manual |
| **Xudanu** | **Span** | **Unbreakable, typed, bidirectional, cross-server** | **First-class, with live updating** | **Per-span authorship** |

Our differentiation is **spans + unbreakable typed links + real
transclusion + per-span provenance**. FR-18 should make these visible at
all times — not buried behind a menu.

### Patterns we adopt from modern tools

- **⌘K command palette** (Linear, Raycast, Notion) for unified nav/search/actions
- **Multi-cursor presence** (Figma, Google Docs) for live collaboration
- **Hover cards on links** (Wikipedia, Are.na) for previewing without leaving
- **Split panes** (VS Code, Obsidian) for parallel reading
- **Block-level commands** (Notion) for `/transclude`, `/link`, `/comment`
- **Lens switcher** (Linear, GitHub) for time-axis vs spatial views

### Writing layout

When the user starts editing (toggles Write on, or has edit access and clicks into the text), the layout subtly shifts:

- The **breadcrumb fades** to 60% opacity (still present, but secondary)
- The **left rail** switches to "Structure" mode (document outline, jump-to-paragraph)
- The **right panel** shows `Outline`, `Transclusions in this doc`, `Recent saves`
- The **bottom lens** switches to `Recent Activity` (other editors, recent saves) by default
- An **edit affordance strip** appears at the top of the document surface (paragraph styles, `/commands`, link button)

The user does NOT navigate away. They're always on the same page.

## Component Breakdown

### 1. Top Bar (global)

| Slot | Content |
|---|---|
| Brand | `[Logo] xudanu` → click goes home |
| Search | `⌘K` opens command palette (search content, authors, topics, actions) |
| `+ Create` | New work / new collection / new trail / import (dropdown) |

### 2. Left Rail (context)

Toggle: **Graph** | **Outline**

#### Graph mode

A miniature version of the document map (reuse `DocumentMapPanel` but smaller). Key differences from the current panel:

- **Categorized nodes** by entity type: Document, Fragment, Person, Concept, Collection, Commentary
- **Icon per category** (Lucide icons or similar):
  - 📄 Document
  - ✂ Fragment
  - 👤 Person
  - 💡 Concept
  - 📚 Collection
  - 💬 Commentary
- **Clustering**: similar documents coalesce at low zoom (force-directed with type-based grouping)
- **Click to focus**: clicking a node either navigates the main pane or opens a split pane (⌘-click)

Below the graph:

**Related Concepts** (with counts):
```
RELATED CONCEPTS
─────────────────
Hypertext              208
Transclusion           123
Non-linear writing      67
Computer-supported      97
Linked documents        86
[ Show more… ]
```

Counts come from a new backend query (`related_concepts`): for each
concept-type work, count of works connected via any typed link.

#### Outline mode

A hierarchical list of the current document's structure (paragraphs,
sections, headings if added) plus a flat list of related works. Useful
for long documents — click to jump to a paragraph.

### 3. Document Surface (center, ~60% width)

#### Header strip

```
Library / Essays / On the Nature of Hypertext     [Follow] [Cite…] [⋯]
─────────────────────────────────────────────────────────────────────
Ted Nelson · Essays · Xanadu Collection · Published 1965 · v23 (2023-11-02)  xan://4f.3
```

- **Breadcrumb**: hierarchical location in collections. Click any segment to navigate.
- **Action buttons**: Follow (subscribe to revisions), Cite (copy xan:// ref), `⋯` (report, export, share)
- **Metadata strip**: author, kind, collection, publish date, version
- **Persistent ID**: always visible, click to copy. Maps to `XudanuTumbler`.

#### Document body

- **Numbered paragraphs** — every paragraph has a margin number (¶1, ¶2, …). Click a number to get a permalink to that paragraph.
- **Margin band** — narrow colored stripe on the left of each paragraph indicating its content type:
  - Blue: contains transclusion(s)
  - Green: contains outbound link(s)
  - Amber: contains annotation(s)
  - Purple: recently edited
- **Span selection** — drag-select to open the selection action popover (link, transclude, annotate, comment, cite)
- **Hover cards** — hovering over a link shows the target's title + first paragraph
- **Inline transclusion expansion** — clicking a transclusion badge expands the transcluded content inline below, indented, with a colored left border. Click again to collapse.

When editing:
- **Slash menu** (`/`) for block commands: `/transclude`, `/link`, `/comment`, `/heading`, `/quote`
- **Presence indicators** — other editors' cursors visible with name labels
- **Save bar** — auto-saves shown subtly; manual save button on access toolbar

### 4. Right Panel (tabs)

Tabs can be reordered by drag. Default order:

| Tab | Content |
|---|---|
| **Provenance** | Author circles + percentages; per-paragraph attribution rollup; "first published" date; "by author" summary |
| **Reuse** | List of works that reuse this content (via transclusion or text similarity). Shows title, year, author. Click to open. |
| **Connections** | 142 connections — type-filterable (Comment, Reference, Disagreement, Quotation, See Also). Click to navigate. |
| **More Info** | Share, export (JSON/HTML/Markdown/PDF), report, settings |
| **Comments** | Threaded comments attached to spans or to the whole work |
| **Annotations** | Per-user annotations; private ones only visible to creator |

The **Provenance tab** has two views:

**Authorship summary (existing pattern)**
```
PROVENANCE
─────────────────────
  ◉ ted       62%
  ◉ andrew    24%
  ◉ mark      14%

First published: 1965-08-12
By author:       Ted Nelson
Collection:      Xanadu Collection
Persistent ID:   xan://4f.3  [⧉]
```

**Per-paragraph view (new, more precise)**
```
PROVENANCE — BY PARAGRAPH
─────────────────────────
  ¶1   ted (100%)
  ¶2   andrew (60%), ted (40%)
  ¶3   ted (100%)
  ¶4   mark (80%), ted (20%)
  …
```

This uses our existing per-span attribution data, rolled up by
paragraph. Hovering a row highlights that paragraph in the document
surface.

### 5. Bottom Lens (one at a time)

Single lens visible at a time; click another lens name to swap. Expand
button takes the lens full-screen (over document surface).

| Lens | What it shows |
|---|---|
| **Origins** | Where the ideas in this work came from. Tree going back through provenance chain, with the current work at the top and sources fanning downward. Reuses `compute_provenance_chain` + `DocumentMapPanel` rendering. |
| **Connections** | How this work connects to others over time. Force-directed graph with a time axis (1960s → 2020s). Filters: by link type, by author, by year. |
| **Timeline** | Revisions of this work. Vertical list with date, version, change description. Highlights "notable" revisions (manually marked or auto-detected). |
| **Diff** | Side-by-side comparison of two revisions. Reuses `ComparePanel` + `work_diff_regions`. Sliders to pick revisions. |
| **Activity** | Recent edits by collaborators; recent comments; recent incoming links from other works. |

The lens row is itself collapsible — click the tab bar to hide it
entirely and reclaim vertical space.

## State Management

The workspace holds:

```typescript
interface WorkspaceState {
  // Primary document being viewed/edited
  primaryDoc: WorkId | null;
  // Optional split-pane secondary document (⌘-click opens)
  secondaryDoc: WorkId | null;
  focusedPane: "primary" | "secondary";

  // Left rail
  leftRailMode: "graph" | "outline" | "hidden";
  graphFilters: NodeCategory[];
  // Right panel
  rightPanelTab: RightPanelTab;
  rightPanelHidden: boolean;
  // Bottom lens
  bottomLens: BottomLens | null;  // null = collapsed
  bottomLensExpanded: boolean;

  // Edit state
  editMode: boolean;
  // Selection state
  selection: { pane: "primary" | "secondary"; start: number; end: number } | null;
  // Theme
  theme: ThemeState;
}
```

Persisted to `localStorage`:
- `xudanu_workspace_layout` (which panels are collapsed, last lens, last rail mode)
- `xudanu_workspace_lastDoc` (last viewed doc — restore on reload)

## Data Model Implications

### Required new fields

```rust
// On Work metadata (in SocialSection or similar)
pub struct WorkMetadata {
    pub kind: WorkKind,  // Document, Fragment, Person, Concept, Collection, Commentary
    pub collection_path: Vec<String>,  // for breadcrumb
    pub published_at: Option<DateTime>,
    pub notable_revisions: Vec<RevisionId>,  // for Timeline lens
}

pub enum WorkKind {
    Document,
    Fragment,
    Person,
    Concept,
    Collection,
    Commentary,
}
```

### Required new queries

```rust
// Get related concept-type works + connection counts
pub async fn related_concepts(&self, work_id: WorkId) -> Vec<(WorkId, String, u32)>;

// Get revisions with metadata for Timeline lens
pub async fn work_revisions(&self, work_id: WorkId) -> Vec<RevisionSummary>;

// Get works that reuse content from this one (via transclusion or text similarity)
pub async fn reuse_for(&self, work_id: WorkId) -> Vec<ReuseEntry>;
```

Most of these can be derived from existing data — no schema migration
strictly needed for v1. `WorkKind` can be stored as metadata tags on
existing works.

### What we can ship without

For v1, **without** `WorkKind`:
- Categorization defaults to "Document" for everything
- The graph still works, just without type-based grouping
- Breadcrumb falls back to flat "Library"

This lets us ship a v1 that's mostly UI recomposition, then layer on
the data model later.

## Responsive Design

Four breakpoints:

### Wide desktop (≥ 1400px)
- All four zones visible
- Document surface ≥ 60% width
- Right panel + left rail both ~20%

### Desktop (1024–1399px)
- Left rail collapses to icon-only by default (hover to expand)
- Right panel narrows to 200px

### Tablet (768–1023px)
- Left rail becomes a slide-out drawer (button in top bar)
- Right panel becomes a slide-out drawer (button in top bar)
- Bottom lens becomes a bottom sheet that swipes up
- Document surface takes full width

### Mobile (< 768px)
- Single pane only (split-pane disabled)
- All panels are drawers / bottom sheets
- Touch-optimized: long-press for selection menu, swipe for panel toggles
- Top bar collapses the nav items into a hamburger menu
- Metadata strip wraps to multiple lines
- Paragraph numbers tap-to-permalink (no hover)

## Implementation Sequence

Built in 7 phases. Each phase is independently shippable.

### Phase 1: Shell + Routing (1–2 weeks)

**Goal:** New workspace skeleton that can show a document, no new features yet.

- New `WorkspaceShell.tsx` component (alongside existing `AppShell.tsx` — they coexist during migration)
- New route: `/explore/:workId` for the new shell
- Top bar with full nav (Create / Explore / Library / Compose + theme picker + user menu)
- Document surface that renders an existing work with `CollaborativeEditor`
- Empty placeholder zones for left rail, right panel, bottom lens
- Theme system integration (uses the FR palettes we just built)

**Exit criteria:** Can navigate to `/explore/<id>` and see a document with the new top bar. Existing AppShell still works.

### Phase 2: Reading Surface Polish (1–2 weeks)

**Goal:** Document surface looks like a finished reading app.

- Breadcrumb component (`Library / Essays / …`)
- Metadata strip (author, kind, collection, publish date, version)
- Persistent `xan://…` ID with copy button (maps to `XudanuTumbler`)
- Numbered paragraphs (margin number column)
- Colored margin bands for paragraphs containing transclusions / links / annotations
- Selection action popover (link, transclude, annotate, comment, cite)
- Hover cards on links (preview target)
- Inline transclusion expansion (collapse/expand on click)

**Exit criteria:** Reading a document in `/explore` is clearly better than in AppShell.

### Phase 3: Right Panel (1 week)

**Goal:** Reuse existing panels in tabs.

- Right panel shell with tab bar
- **Provenance tab**: pulls in `AttributionPanel`, adds author-circle summary + per-paragraph view
- **Connections tab**: pulls in `ConnectionsSection`
- **Comments tab**: pulls in `AnnotationPanel` (comments + annotations)
- **More Info tab**: share, export, report

**Exit criteria:** All existing per-feature panels accessible from one place.

### Phase 4: Left Rail (2–3 weeks)

**Goal:** Graph + outline variants.

- Mini graph using `DocumentMapPanel` in a constrained size
- Outline mode (paragraph jump list)
- Related concepts list (needs new backend query — `related_concepts`)
- Backwards-compatible: if `WorkKind` isn't set, everything is "Document" — no visual change
- Future-ready: graph rendering supports node-type icons when `WorkKind` becomes available

**Exit criteria:** Left rail useful for navigation, even without full `WorkKind` tagging.

### Phase 5: Bottom Lens (2–3 weeks)

**Goal:** Multi-lens view of connections/history.

- Lens selector tab bar
- **Origins lens**: vertical tree using `compute_provenance_chain`
- **Connections lens**: force-directed graph with time axis (new code; consider d3-force or react-force-graph)
- **Timeline lens**: list of revisions (needs new `work_revisions` query — but revisions already exist, just need surfacing)
- **Diff lens**: reuse `ComparePanel`
- **Activity lens**: recent edits, comments, incoming links
- Expand-to-fullscreen mode for any lens

**Exit criteria:** User can switch between four lenses without leaving the page.

### Phase 6: Writing Mode + Command Palette (2 weeks)

**Goal:** Same surface, full writing capability.

- Edit affordance strip at top of document (when user has edit access)
- Slash menu (`/transclude`, `/link`, `/comment`, etc.)
- Presence indicators for other editors
- ⌘K command palette (search + actions + navigation)
- Compose mode preset: hides left rail, expands right panel outline
- Edit-mode state transitions (subtle visual shifts, no navigation)

**Exit criteria:** User can fully edit a document in `/explore` without needing AppShell.

### Phase 7: Split Pane + Responsive (2 weeks)

**Goal:** Multi-document reading + mobile support.

- ⌘-click a link → opens second pane
- Focus ring on active pane; right panel and bottom lens follow focus
- Tablet breakpoint: slide-out drawers
- Mobile breakpoint: bottom-sheet pattern, single pane only
- Touch interactions: long-press selection, swipe for panels

**Exit criteria:** Useful on iPad and phone.

### Phase 8: Polish + Migration (1 week)

**Goal:** Ready to make this the default.

- Smooth animations on panel transitions
- Performance pass (virtualization for long docs, lazy graph rendering)
- Keyboard shortcuts (vim-style navigation optional)
- Set `/explore` as the default route
- Keep AppShell accessible at `/edit/:workId` for legacy

**Exit criteria:** Default experience is the new workspace.

**Total estimate: 10–15 weeks of focused work**, but heavily paralellizable
across phases (e.g. backend queries for Phase 4 and Phase 5 can be built
in advance).

## Alternatives Considered

### Alternative A: Evolve AppShell incrementally

Don't introduce a new shell; instead add zones to AppShell over time.

**Pros:** No new code; users see gradual improvements.
**Cons:** AppShell has accumulated cruft (WorkspacePage.tsx dead code, ContextPanel layout assumptions). A clean slate lets us rethink layout defaults. Also AppShell is tightly coupled to single-doc editing; multi-pane and lenses fight its structure.

**Decision:** Build new `WorkspaceShell`. Keep AppShell working for editing until Phase 8.

### Alternative B: Modal / dialog pattern

Each lens (origins, timeline, diff) is a modal that opens on top of the document.

**Pros:** Doesn't change the document layout.
**Cons:** Modals interrupt flow. The whole point is that these views are lenses on the same document — they should be visible alongside it, not on top.

**Decision:** Use bottom lens row, not modals. Modals only for genuinely one-off actions (settings, share).

### Alternative C: Sidebar tabs instead of bottom row

Put origins / connections / timeline / diff as additional tabs in the right panel.

**Pros:** Simpler layout (only 3 zones).
**Cons:** Right panel is narrow (200–240px). Origins view and time-axis graph need width. Putting them there would either make them cramped or require expanding the panel, which then steals from the document surface.

**Decision:** Bottom lens row, expandable to full-screen, is the right tradeoff.

### Alternative D: Block-based editing (Notion/ProseMirror style)

Switch from span-based CRDT to block-based.

**Pros:** Easier slash menu, cleaner structure.
**Cons:** Xudanu's entire model is span-based. Transclusion, attribution, link migration all operate on character spans. Switching to blocks would break the core differentiators.

**Decision:** Stay span-based. Slash menu operates at the cursor position; blocks are a rendering/affordance layer on top of the span model.

## Open Questions

These need decisions before or during implementation:

1. **Notable revisions**: How does a revision become "notable" in the Timeline lens? Manual flag? Auto-detected (size threshold)? Both?
2. **Follow a work**: What does "Follow" actually do? Notify on revision? Notify on new incoming links? Both? Where do notifications appear?
3. **Cite action**: What does the citation look like? Plain `xan://` URL? BibTeX? Both with a format picker?
4. **Hover cards**: What's the latency budget? Need backend support for fast preview fetches.
5. **Concept vs Tag**: Is a "Concept" a kind of work (with its own page) or a tag applied to works? Both? (Recommend: works of kind=Concept that you can link to like any other work.)
6. **Commentary**: Is commentary a work kind (separate doc) or an annotation (attached to a span)? (Recommend: both — commentary can be either, depending on whether the author wants a standalone doc or a marginal note.)
7. **Collections**: How does a work get added to a collection? Manual? Auto-derived from links? Both?
8. **Mobile editing**: Do we support writing on mobile, or read-only? (Recommend: read-only for v1; writing comes later.)
9. **Offline support**: PWA-style offline reading? Important for fieldwork use cases.

## Success Criteria

- A first-time user can: open a work, see its connections, follow a transclusion, open a second pane, switch lenses, all without leaving the page or opening a menu buried 3 levels deep.
- An author can: write a paragraph, transclude a passage from another work, link to a related concept, comment on someone else's paragraph — all from the same surface they were just reading on.
- A researcher can: trace the origin of an idea backward through the provenance chain, see how it spread forward through connections over time, and diff two revisions — all in one session, one URL.
- The page loads in under 2 seconds on first paint (virtualized editor, lazy panels).
- The page works on a 768px tablet without horizontal scroll.
- The page differentiates visibly from Notion/Roam/Obsidian within 5 seconds of viewing — a visitor should immediately see typed links, transclusion markers, and the xan:// ID.
