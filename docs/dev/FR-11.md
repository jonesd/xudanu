# FR-11: Compound Document Builder

> The compound builder is Xanadu's core authoring tool: assembling new
> documents from passages of existing works via transclusion. This is the
> EDL (Edit Decision List) model — the document IS a list of content
> addresses, assembled and presented as readable text. Gold's primary
> document model was compound-based; our inline transclusion
> infrastructure already supports it but lacks a proper authoring UI.

## Goal

Provide a visual authoring environment where users build documents from
passages of multiple source works, with live preview, reordering, and
structure visibility. The resulting document is a compound of original
content and transcluded passages, each maintaining its provenance.

## Background

### Gold's compound model

Udanax-Gold's document model was inherently compound. Documents were
built from "links" and "included content" — the text wasn't stored as a
flat string but as a structure of references to content in other
documents. This is the same concept as Nelson's EDL.

### Our current infrastructure

We already have:
- `RangeElement::Transclusion` inline in the O-tree (single source of truth)
- 32-level recursive resolution with cycle detection
- Span migration through edits (transcluded passages track source changes)
- Compound panel showing structure
- Content fingerprinting (BLAKE3) for content identity
- Provenance chains tracing content origin history
- `compoundSpanRanges` and `compoundSourceTitles` in the frontend

### What's missing

The authoring workflow: there's no way to visually assemble a document
from multiple sources. Current transclusion is one-at-a-time, manual
placement, no overview of the compound structure.

## Visual Design

### Assembly Mode

When the user enters "Build" mode, the screen splits into:

```
┌────────────────┬──────────────────────────┬────────────────┐
│  Source Pool   │   Compound Document       │  Structure     │
│                │   (live preview)          │  Outline       │
│ ┌────────────┐ │                           │                │
│ │ Source A   │ │  Original intro text...   │ 1.[Original]   │
│ │ "drag to   │ │                           │   Intro        │
│ │  include"  │ │  ┌─────────────────────┐ │                │
│ └────────────┘ │  │ [Transcluded from A]│ │ 2.[From A]     │
│ ┌────────────┐ │  │ "The definition..." │ │   Definition   │
│ │ Source B   │ │  └─────────────────────┘ │                │
│ │            │ │                           │ 3.[Original]   │
│ └────────────┘ │  Original analysis...     │   Analysis     │
│ ┌────────────┐ │                           │                │
│ │ Source C   │ │  ┌─────────────────────┐ │ 4.[From B]     │
│ │            │ │  │ [Transcluded from B]│ │   Interpret    │
 │ └────────────┘ │  │ "The court held..." │ │                │
│                │  └─────────────────────┘ │ 5.[From C]     │
│ + Add source   │                           │   Commentary   │
│                │                           │                │
└────────────────┴──────────────────────────┴────────────────┘
```

**Left panel — Source Pool:**
- Library of available source documents
- Click a source to expand and read it
- Select text → "Include in document" button (or drag to center)
- Each source shows how many passages already included
- "+ Add source" opens work picker / search

**Center — Compound Document (live preview):**
- The document being built, rendered as readable text
- Transcluded passages shown with subtle colored background
- Source label badge on each transclusion
- Click transclusion → highlight source in left panel
- Type original text between transclusions
- Drag transclusions to reorder

**Right panel — Structure Outline:**
- Numbered list showing document composition
- Each entry: [Original] or [From: Source Name]
- Drag to reorder
- Click entry → scroll center to that passage
- Click entry → scroll source to that passage
- Shows the document as an EDL (list of content references)

### Integration with Perspective View

The Perspective view and the compound builder share the same spatial
concept. A natural workflow:

1. Open Perspective view on a topic
2. See connected source documents arranged spatially
3. Enter "Build" mode from Perspective
4. Drag passages from neighbors into the center document
5. The center document becomes a compound of sources
6. Exit Build → return to Perspective showing the new relationships

This connects FR-9 (Perspective) and FR-11 (Compound Builder) into a
unified authoring environment.

## Features

### Phase 1: Basic assembly (3-5 days)

1. **Build mode toggle**
   - Button in doc-toolbar: "Build" (next to Perspective)
   - Enters assembly mode with three-panel layout
   - Center column: current document text
   - Left column: source pool (initially empty)
   - Right column: structure outline

2. **Source selection**
   - "Add source" opens work picker (reuse LibrarySlideOut)
   - Added sources show in left panel with preview text
   - Multiple sources can be open simultaneously
   - Source text is read-only

3. **Include passage**
   - Select text in a source → "Include" button appears
   - Passage added to compound at cursor position (or end)
   - Transclusion created via existing `handlePlaceTransclusion`
   - Source label badge appears on included passage
   - Structure outline updates

4. **Structure outline**
   - Right panel shows document composition
   - Each entry: type (Original/Transcluded) + source + first words
   - Click entry → scroll to that passage in center
   - Shows the document as it would export as EDL

5. **Live editing**
   - Type original text between transclusions
   - Standard editor controls work (bold, italic)
   - Transcluded passages are read-only inline (highlighted)
   - Delete transclusion via right-click or structure outline

### Phase 2: Refinement (3-5 days)

6. **Drag to reorder**
   - Drag transclusions up/down in the document
   - O-tree CRDT supports position changes
   - Structure outline updates live

7. **Drag from source to compound**
   - Drag selected text from left panel to center
   - Drop position determines insertion point
   - Visual drop indicator (line between paragraphs)

8. **Source highlighting**
   - Click transclusion in center → scroll source to that passage
   - Hover transclusion → tooltip with source title and provenance
   - Active source highlighted in left panel

9. **EDL export**
   - "Export as EDL" button
   - Generates JSON list of content references
   - Format compatible with Xanadu EDL concept
   - Includes source work ID, span positions, content hash

10. **Compound from trail**
    - Convert a trail (reading sequence) into a compound document
    - Each trail stop becomes a transcluded passage
    - User adds connecting text between stops
    - Result: a curated anthology built from the docuverse

### Phase 3: Advanced (future)

11. **Perspective integration**
    - Enter Build mode from Perspective view
    - Drag passages from neighbor columns into center
    - Sources auto-populate from Perspective neighbors

12. **Fuzzy matching**
    - When user types text similar to a source passage
    - Suggest: "This resembles a passage in [Source]. Transclude?"
    - Uses content fingerprint infrastructure

13. **Version comparison**
    - When a source document is revised
    - Show which transclusions are affected
    - Option to update to latest source version

14. **Citation generation**
    - Auto-generate citations from transclusion provenance
    - Format: MLA, APA, Chicago, legal
    - Inline citations + bibliography

15. **Template compound**
    - Pre-defined compound templates (legal brief, literature review)
    - Template defines required sections + suggested source types
    - User fills in by selecting passages

## Data Model

No changes needed. The compound document is already supported:

```
O-tree elements:
├── RangeElement::Text("Original intro paragraph")
├── RangeElement::Transclusion {
│     source_work_id: 0x415,
│     char_start: 120,
│     char_end: 340,
│     content_hash: [BLAKE3],
│   }
├── RangeElement::Text("Original analysis")
├── RangeElement::Transclusion {
│     source_work_id: 0x422,
│     char_start: 56,
│     char_end: 180,
│     content_hash: [BLAKE3],
│   }
└── RangeElement::Text("Original conclusion")
```

The structure outline reads the O-tree elements directly.
Transclusion placement uses existing `handlePlaceTransclusion`.
Span migration keeps positions valid through edits.
Provenance chains trace each transclusion to its origin.

## Connection to Federated Wiki

Federated Wiki's fork model is document-level assembly. Our compound
builder is passage-level assembly. Both serve the "build from existing"
need, but at different granularities:

- **Fork** (FedWiki): copy whole page, edit independently. Good for
  derivative works, translations, adaptations.
- **Compound** (Xudanu): assemble from specific passages of multiple
  sources. Good for anthologies, legal briefs, literature reviews,
  argumentation that builds on multiple sources.

We could support both: compound for passage-level, fork for
document-level. A fork creates a new work with a provenance link to
the original. A compound creates a new work from many transcluded
passages.

## Connection to Gold

Gold's primary document creation model was compound. The "bazik"
facility and the ent/enfilade system were designed for building
documents from transcluded content. Our compound builder is the
modern equivalent — same concept, different implementation:

| Gold concept | Xudanu equivalent |
|---|---|
| Enfilade | O-tree CRDT |
| Tumbler address | BeId + char position |
| Transclusion link | RangeElement::Transclusion |
| Again() (provenance walk) | compute_provenance_chain |
| Intercomparison | find_shared_regions + Perspective view |
| Bazik (assembly) | Compound Builder (this FR) |

## Priority Rationale

The compound builder is the **creation tool** that makes the docuverse
structure authorable. Without it:
- Users can create documents and link them (typed links)
- Users can view spatial relationships (Perspective)
- But users can't easily BUILD documents from multiple sources

The compound builder completes the authoring loop:
- **Link** = "this document relates to that document" (FR-4, shipped)
- **Transclude** = "this passage comes from that document" (inline, basic)
- **Compound** = "this document is assembled from many passages" (FR-11, needed)

It's the difference between having ingredients and having a kitchen.
