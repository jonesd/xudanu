### Key insight: Gold's comparison was fed by content identity

Gold's TextComparator did NOT compare raw text. It first called the backend
enfilade comparison (`orig compare: final`) to get content-identical fragments,
then ran LCS over those fragments. This means:

1. Content that was transcluded (shared object identity) was detected for free
2. The LCS operated on maximal matching runs, not characters/lines
3. Move detection worked on content-identical fragments (move = delete + insert of same fragment)

Xudanu has the same content-identity infrastructure (BLAKE3 fingerprints) but
doesn't feed it into the diff algorithm. Our ComparePanel does raw text matching.

## Design: Best-of-Breed Approach

### Principle: Content-addressed diff (Gold's key insight, modernized)

The best comparison tool combines:

1. **Content identity** (Gold's approach, modernized with BLAKE3)
   - First pass: find content-identical elements between documents
   - This detects transclusion, quotation, and shared passages for free
   - No string comparison needed — fingerprint set intersection

2. **Optimal text alignment** (modern diff algorithms)
   - Second pass: align unmatched text using Myers diff
   - Character-level precision for fine-grained changes
   - Semantic cleanup for readability

3. **Move detection** (Gold's FirstFitMaker, modernized)
   - Third pass: detect deleted+inserted pairs with matching content
   - Score by move count, distance, and size
   - Visualize as move arrows

4. **Interactive 3-way merge** (modern, not Gold)
   - When two documents derive from a common base
   - Surface conflicts for user resolution
   - Use backend three_way_merge with real alignment

### Comparison visualization layers

```
Layer 1: Content-identical passages (Gold-style sharedWith)
  └─ Green: this passage exists in both documents (same content)
  └─ Detected via BLAKE3 fingerprint intersection

Layer 2: Text-level changes (modern diff)
  └─ Red: deleted text
  └─ Green: inserted text
  └─ Yellow: modified text (character-level diff within matched region)
  └─ Detected via Myers diff on unmatched segments

Layer 3: Moves (Gold-style FirstFitMaker)
  └─ Blue arrows: this passage was moved from position X to position Y
  └─ Detected by pairing content-identical delete+insert

Layer 4: Structural elements (Xudanu-specific)
  └─ Purple: transclusion changed source
  └─ Orange: link added/removed
  └─ Cyan: annotation changed
  └─ Detected by comparing RangeElement types
```

## Implementation Plan

### Phase 1: Fix and revive existing comparison (3-5 days)

**Goal**: Make ComparePanel and ThreeWayDiffPanel work correctly in the live UI.

1. **Fix ComparePanel**
   - Fix fuzzy threshold (20% → 35%, match tooltip)
   - Add character-level diff option (upgrade from word-level)
   - Use backend `find_shared_regions` result to drive alignment
   - Fix the split view for documents of very different lengths

2. **Revive ThreeWayDiffPanel**
   - Port from dead WorkspacePage to live AppShell
   - Replace index-based paragraph alignment with content-fingerprint alignment
   - Wire to backend `work_merge` (wire op 0x0322) instead of client-side merge
   - Add conflict resolution UI (accept A / accept B / manual edit)

3. **Add character-level diff**
   - Implement Myers diff at character granularity
   - Semantic cleanup: merge adjacent single-char changes into word/phrase changes
   - Toggle between word-level and character-level in the UI
   - Color coding: green (insert), red (delete), yellow (modify)

4. **Version timeline**
   - Port VersionGenealogyPanel from dead WorkspacePage
   - Show revision history as a graph (not just a flat list)
   - Click any two revisions to compare them

### Phase 2: Content-addressed comparison (3-5 days)

**Goal**: Gold-style content identity as the foundation of comparison.

5. **Feed content fingerprints into diff**
   - Before running text diff, query `find_shared_regions(work_a, work_b)`
   - Mark content-identical passages as "shared" (no diff needed)
   - Only run text diff on non-shared regions
   - This makes transclusion detection free in comparison

6. **Move detection**
   - After diff, scan delete+insert pairs for content-identical fragments
   - Score candidate moves by count, distance, and fragment size
   - Visualize moves as colored arrows in the split view
   - Gold's FirstFitMaker algorithm, adapted for our fingerprint infrastructure

7. **Structural element comparison**
   - Compare RangeElement types between editions
   - Show transclusion changes (source work changed?)
   - Show link changes (added/removed/retyped)
   - Show annotation changes (added/removed/resolved)
   - Visualize as structural markers alongside text diff

### Phase 3: Interactive 3-way merge (3-5 days)

**Goal**: Merge two divergent documents with conflict resolution.

8. **Wire frontend to backend work_merge**
   - Add `workMerge(baseId, workAId, workBId)` to CrdtSyncClient
   - Backend uses element-level three_way_merge with real alignment
   - Returns merged work + conflict list
   - Stamp with DerivationMethod::Merge provenance

9. **Conflict resolution UI**
   - For each conflict: show Base, A, B side by side
   - Accept A / Accept B / Manual edit / Auto-merge (LWW)
   - Preview merged result before committing
   - Conflict markers in the merged document

10. **Merge from comparison**
    - When comparing two documents that share a common base
    - "Merge" button opens the 3-way merge view
    - Base is auto-detected from provenance chain
    - If no common base, offer side-by-side merge (pick from each side)

### Phase 4: Advanced visualization (future)

11. **Heat map overlay**
    - Show change density across the document
    - Smooth scroll: zoom from bird's-eye (whole document) to detail
    - Color intensity = number of changes per region

12. **Semantic diff**
    - AST-based comparison (understand structure, not just text)
    - Detect paragraph reordering, sentence restructuring
    - Requires NLP or language-specific parsing

13. **Comparison history**
    - Track what was compared previously
    - "Compare with" dropdown remembers recent comparisons
    - Save comparison sessions for later reference

14. **Export comparison report**
    - Generate a standalone HTML report of the comparison
    - Include connection diagrams, diff statistics, move arrows
    - Shareable with collaborators
