## Phase 4: SequenceSpace for Tumbler Addressing

### Current state

Cross-server addresses use string-based tumblers: `"alice.example.com".5.3.10.7`.
These are stored as strings in `CrossServerRef` and compared via string equality.

### What SequenceSpace would add

`SequenceSpace` (already implemented in `space/sequence.rs`, ~1250 LOC, tested)
provides proper algebraic tumbler positions:

- **Prefix queries**: "find all content under alice.com.5.*"
- **Address migration**: tumblers shift when server namespace changes
- **Tumbler arithmetic**: compose, intersect, compare tumbler regions
- **Canonical ordering**: lexicographic ordering of tumbler sequences

### Implementation

1. Replace `String` tumbler fields in `CrossServerRef` with `SequencePos`
2. Update JSON serialization to convert between string and SequencePos
3. Update cross-server resolution to use SequenceSpace prefix matching
4. Update server directory to index by SequenceRegion
5. Update backlink notification to carry SequencePos

### Effort: Large (2-3 weeks)
### Risk: Medium — changes wire protocol and persistence format
### Near-term need: Low — string tumblers work for current features
### Trigger: When we need efficient cross-server content discovery at scale

## Phase 5: CrossSpace for Document Metadata

### What it adds

`CrossSpaceN` (already implemented in `space/cross_n.rs`, ~740 LOC, tested)
enables multi-dimensional document maps:

- `(work_id, char_position)` as a single algebraic position
- `(server_id, work_id, position)` for cross-server queries
- Spatial queries: "find all content in rectangle [work_a..work_b] × [pos_10..pos_50]"
- Configurable dimension ordering for different query patterns

### Implementation

1. Define `DocumentPosition = Cross2<IntegerSpace, IntegerSpace>` for (work, position)
2. Build a `CrossSpaceN` index over all link/transclusion spans
3. Replace per-work link iteration with spatial queries
4. Enable "show me all links in these 5 works between positions 100-500"

### Effort: Large (2-3 weeks)
### Risk: Low — new feature, doesn't change existing code
### Near-term need: None — RegionIndex handles single-work queries
### Trigger: When Perspective View needs efficient multi-document queries

## Phase 6: Wire RegionIndex into Server

### Current state

`RegionIndex<T>` exists in `edition/region_index.rs` with 11 tests but is
not used by the server. Link queries iterate over all links linearly.

### What it adds

- O(log n) link queries by position range
- "Find all links intersecting positions 100-200" without scanning all links
- Efficient backlink resolution for specific passages
- Viewport-based connection filtering for Perspective View

### Implementation

1. Add a `RegionIndex<link_id>` field to `Server` (or per-work in `WorkState`)
2. Populate on link create/delete and on checkpoint restore
3. Replace linear scans in `server.rs` link query methods
4. Add a `links_in_region(work_id, start, end)` server method
5. Expose via WebSocket for the frontend

### Effort: Medium (3-5 days)
### Risk: Low — additive, doesn't change existing query results
### Near-term need: Medium — would speed up connection panel for works with many links

## Phase 7: Fix Greedy Alignment in three_way.rs

### Current state

`compute_alignment()` in `three_way.rs` uses greedy longest-seed-first matching.
This is fast but not optimal — interleaved edits can produce wrong alignments.

### What a fix would add

- Myers O(ND) algorithm (same family as `diff`/Git) for optimal alignment
- Better merge results when both sides edit interleaved regions
- Fewer false conflicts

### Implementation

1. Port Myers 1986 O(ND) to element-level alignment
2. Replace `compute_alignment()` with the Myers-based version
3. Add equivalence tests proving same results on existing test cases
4. Add new test cases with interleaved edits

### Effort: Medium (3-5 days)
### Risk: Medium — changes core merge algorithm, could affect CRDT
### Near-term need: Low — current greedy works for most real-world edits

## Phase 8: Real FilterSpace

### Current state

`FilterSpace` in `space/filter.rs` is tag-based with `pass_joint` stubbed.

### What it adds

- Region-based filter matching (not just tags)
- Tree pruning via `Joint` for efficient canopy-style queries
- "Find all links whose span is a subset of / intersects region R"

### Implementation

1. Add `FilterSpace` variant that wraps a real `CoordinateSpace`
2. Implement `Filter::matches_region(region)` using intersection tests
3. Implement `Joint::pass(region)` for tree pruning
4. Wire into canopy traversal for link/transclusion queries

### Effort: Medium (3-5 days)
### Risk: Low — new feature
### Near-term need: Low — RegionIndex covers practical queries

## What NOT to Do

- **Replace XnRegion with trait objects everywhere** — adds indirection, removes inlining
- **Delete the space module** — it's a correct reference and enables Phases 4-5
- **Force all code through traits** — i64 is sufficient for 99% of operations
- **Rewrite edition layer** — the practical types work and are well-tested
