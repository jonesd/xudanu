# FR-81 — Ingress provenance: honest claims for non-typed content

**Status:** draft for review (September 2026)
**Prior art in-tree:** `historical_attestation` (provenance.rs), web
shadows (FR-79), `DerivationMethod`, the attribution log + OTS
anchoring (FR-60). This FR generalizes a pattern the system already
proves twice.
**Related:** provenance review (see `~/Documents/xudanu-provenance-review.txt`
and the business notes); closes the known LLM-attribution gap under
the same design.

## Why

Provenance today is anchored to *typing*: spans are signed because a
session's key produced keystroke-level CRDT deltas. But documents
fill with content that arrived by other doors — pasted, imported,
OCR'd, dictated, generated, fetched, captured, received from peers.
For each of those, "who typed it" is the wrong question, and an
honest system must not pretend it was typed.

The business framing makes it sharp: "evidence-grade documents"
must hold for EVERYTHING in the document, not just the typed parts.
A provenance model that silently upgrades a paste to authorship is
not evidence — it is a fabricated claim with a signature on it.

## The model

**Provenance is a chain of signed claims about origin and
transformation.** Typing is the degenerate hop. Every ingress hop
carries the same four things:

    { method, input_digest(s) → output_digest, attestor, timestamp } + signature

Three rules make it secure:

1. **asserted_by ≠ authored_by.** The attestor signs that the
   ingress HAPPENED and what the bytes are; an original author may
   be *claimed* (unverified) — never signed-for as fact. The import
   case already models this (`historical_attestation`: server
   attests the import; author id is claimed).
2. **Method labels are honest.** `Generated` is never `Authored`;
   `OCR` carries engine and confidence; `Fetched` carries the URL
   and the fetch hash (web shadows already do exactly this).
3. **Chains compose.** Typed by A → transcluded by B → OCR'd by C:
   each hop is its own signed record; the derivation chain is the
   provenance. No hop vouches for what it cannot see.

## The ingress table

| Ingress | Signed claim | Attestor |
|---|---|---|
| Keystrokes | span authorship (today's model) | user session key |
| Paste | "bulk insert of blob H; source unattested" | client (see §client) |
| File import | "imported bytes H at T; claimed author X (unverified)" | account + server |
| OCR | "image H1 → text H2 via engine E, confidence c" | engine/device |
| Dictation | "audio H1 → text H2 via engine E" | engine/device |
| LLM generation | "generated by model M from prompt hash P; invoked by user U" | invocation (the known `AuthorType::Llm` gap — closed by this FR) |
| Web fetch | "URL U → content H at T" | server (FR-79 shadows — done) |
| Camera/capture | "captured by device D at claimed T" | device |
| Federated | carries the origin server's signed chain | peer |

## Timing — three layers, one honest limit

1. **Event time** — claimed by the attestor. Recorded, never trusted.
2. **Receipt time** — server-signed when the assertion enters the
   attribution log (tamper-evident chain).
3. **Anchor time** — OTS/BTC on chain heads: "this assertion
   existed by block N."

**The not-before limit (accepted, not solved):** non-typed content
cannot prove it existed before its first ingress. Pasted text
claiming 1997 provenance is recorded `asserted_at: today,
claimed_origin: 1997 (unverified)` — correct behavior. Typed content
earns its not-before from the keystroke stream; fetched content gets
a weak one from headers; photo metadata is recorded, never trusted.

## Design

### 1. Extend DerivationMethod (edition layer)

Today: `Transclusion | Merge | Import`. Add:

    Ocr { engine: String, confidence: f32 }
    Dictation { engine: String }
    Generated { model: String, prompt_digest: [u8; 32] }
    Fetched { url: String, fetch_digest: [u8; 32] }   // mirrors FR-79
    Captured { device: String }

Serialized with `#[serde(default)]` variants — wire and persistence
backward compatible (postcard discipline).

### 2. Ingress attestation record (the new unit)

    IngressAttestation {
        method: DerivationMethod,      // honest label
        input_digests: Vec<[u8;32]>,   // what it came FROM (image, audio, URL body, prompt)
        output_digest: [u8;32],        // the text/edition bytes it produced
        attestor: BeId,                // account or server club
        attestation_kind: User | Server | Device | Engine,
        event_time: u64,               // claimed
        signature,                     // Ed25519, domain-separated:
    }                                  // xudanu/v1/ingress-attestation

- Appended to the attribution log → inherits tamper-evidence and
  rides the OTS anchor rounds.
- New domain constant (the four existing domains set the pattern;
  ingress claims must not be replayable as span authorship).

### 3. Wire surface (minimal)

- `ingress_attest { work_id, position?, attestation }` — admin or
  the editing session; records the hop. Intended caller: the CLIENT
  at the moment of ingress, not after.
- `work_create` / `element_insert` gain an optional `via:
  IngressAttestation` — one round trip for import-shaped flows.
- No new read op: attestations surface through attribution queries
  and the existing provenance panels.

### 4. The client attests method — and the delta shape checks it

The editor knows paste from typing; the CRDT delta stream also
knows (40 keystroke deltas ≠ one bulk insert). Therefore:

- Client attaches method attestation to bulk inserts at ingress
  time (paste dialog: "pasted from <source?, unattested>").
- Server-side integrity signal: **bulk insert without a method
  attestation** is flagged in the attribution record as
  `method: Unattested { delta_span_bytes }`. Not a block, not a
  judgment — an honest hole in the record where a claim is missing.
- This makes "pasted it and called it typing" detectable from the
  record's shape — cheap, and it falls out of data we already have.

## Staging

- **Stage 1 (closes the known gaps):** DerivationMethod variants +
  IngressAttestation record + domain separation + attribution-log
  append + `Generated` stamped on the LLM path (the LLM gap closes
  here) + `Unattested` bulk-insert flagging. No UI beyond the
  provenance panel showing the new kinds.
- **Stage 2 (client honesty):** editor attaches method attestations
  at ingress (paste/import dialogs); shadow fetches recorded as
  `Fetched` hops end-to-end.
- **Stage 3 (device/engine attestations, optional):** dictation and
  OCR engines sign their own hops; device capture attestation.
  Only if a deployment needs it — the record shape reserves the
  `attestation_kind` now so it is additive later.

## Exit criteria

- [ ] paste recorded as Unattested or Pasted (never Authored) —
      provenance panel shows it honestly
- [ ] import recorded as Import with claimed-author (unverified)
- [ ] LLM generation stamped Generated{model, prompt_digest},
      invoked-by user — the attribution gap closed
- [ ] web shadow creation emits a Fetched hop (FR-79 alignment)
- [ ] ingress attestations in the attribution log; chain verify
      covers them; OTS round anchors them with everything else
- [ ] roundtrip: typed→transcluded→OCR'd chain renders each hop
      with its own attestor and method

## Open questions (for review)

1. **Prompt digest for Generated** — hash only, or store the prompt
   text in an evidence field? (Privacy vs. auditability; probably
   hash by default, opt-in text for enterprise.)
2. **Engine/Device signatures (Stage 3)** — who holds keys for an
   OCR engine? Probably: the invoking client signs and the engine
   identity is a *claimed* field until engines can attest — same
   honesty rule one level down.
3. **Bulk-insert threshold** — bytes or delta-count based? Needs a
   number that doesn't flag legitimate fast typists (suggest:
   single delta > 120 bytes with no preceding keystroke deltas in
   the session window).
4. **Editing after ingress** — the OCR text gets fixed by a human;
   spans of the fix are Authored, the rest stays Ocr'd. Confirm the
   span model handles mixed provenance cleanly (it should — spans
   are independent).

## Non-goals

- Verifying external claims (that a fetched page really said X at
  its origin — that is the shadow's problem, solved by hash+time).
- Digital signatures ON captured media (camera signing) — Stage 3+
  at the earliest, likely never needed.
- Trust scoring of attestors — that is endorsement's job (the
  reputation layer orders claims; it does not alter them).
