# FR-14: Connect Space Algebra to Live Code Path

> The space algebra (`src/space/`) is complete and well-tested but
> completely disconnected from the live system. Connecting it unlocks
> cleaner span migration, native diffing, better merge, and region-based
> link/transclusion queries — replacing ~300 lines of hand-rolled
> imperative code with algebraic operations.

### What's disconnected

The live system uses three separate hand-rolled abstractions:
- `edition/xn_region.rs` — XnRegion (i64 transition lists)
- `edition/mapping.rs` — Mapping enum (Empty/Simple/Composite)
- `edition/shared_mapping.rs` — SharedMapping (sorted pair lists)

And hand-written imperative code for:
- Span migration through text deltas (`compound.rs:31-105`)
- Three-way diff alignment (`three_way.rs:210-340`)
- Content-shared region finding (`edition.rs:978-1069`)
- Backfollow position mapping (`backfollow.rs`)

## Tier 1: Core Algebraic Operations

### 1. `Mapping::transformedBy(Dsp)` — Replaces Span Migration

**Current code** (`compound.rs:31-105`):
```rust
fn map_span_through_delta(span_start, span_end, ops: &[TextDeltaOp]) -> (usize, usize) {
    let mut current_start = span_start;
    let mut current_end = span_end;
    for op in ops {
        match op {
            Retain(n) => { /* advance both */ }
            Insert(text) => { /* shift start/end if before */ }
            Delete(n) => { /* shrink/shift */ }
        }
    }
    (current_start, current_end)
}
```

**With algebra**:
```rust
let edit_dsp = build_dsp_from_delta_ops(ops);
let new_span = old_span.transformed_by(edit_dsp);
```

**Unlocks:**
- Link span migration through any edit composition (not just sequential ops)
- Transclusion span migration (currently duplicated code)
- Annotation span migration through merges
- Backfollow index updates when source text changes
- Reversible migration via `Dsp::minus`

**Implementation:**
1. Add `transformedBy` to the `Mapping` trait in `space/mapping.rs`
2. Implement for `SimpleMapping`: `result.offset = self.offset + dsp.of(0); result.region = self.region.transformed_by(dsp)`
3. Implement for `CompositeMapping`: map each component
4. Add `build_dsp_from_delta_ops` in `edition/` that converts delta ops to a `Dsp`
5. Replace `map_span_through_delta` calls in `compound.rs` and `server.rs`

**Files affected:**
- `space/mapping.rs` — add `transformed_by` method
- `space/traits.rs` — add method to Mapping trait
- `edition/compound.rs` — replace hand-written migration
- `server/server.rs` — replace migration calls (lines 2306-2323)
- `server/otree_crdt.rs` — annotation migration (lines 650-663)

### 2. `Region::delta` — Native Diff Operation

**Current code** (`three_way.rs:210-340`): Hand-written `compute_alignment` + `build_segments` that reconstruct what is essentially `Region::delta` through fingerprint seeds and segment enums.

**With algebra**:
```rust
let changed = region_a.delta(&region_b);  // (a-b) ∪ (b-a)
let only_a = region_a.minus(&region_b);
let only_b = region_b.minus(&region_a);
let shared = region_a.intersect(&region_b);
```

**Unlocks:**
- Cleaner three-way diff (diff = delta of regions)
- "What changed" queries for comparison UI
- Change-set computation for incremental checkpointing
- Heat-map generation (density of changed regions)
- Move detection (delta pairs with matching content)

**Implementation:**
1. Add `delta` to `Region` trait: `fn delta(&self, other: &Self) -> Self { self.minus(other).union(&other.minus(self)) }`
2. Add to `XnRegion` (already has `minus` and `union`)
3. Use in `three_way.rs` to simplify diff computation
4. Use in comparison UI to compute "changed regions" for heat map

**Files affected:**
- `space/traits.rs` — add `delta` default method
- `edition/xn_region.rs` — verify `minus`/`union` correctness for delta
- `edition/three_way.rs` — simplify diff computation

### 3. Connect `crate::space` to `edition/`

**The bridge:** Make `IntegerRegion` (from `space/integer.rs`) the canonical
type, with `XnRegion` as its inner representation. Edition operations
return `IntegerRegion`; server code uses the trait interface.

**Implementation:**
1. Add `From<XnRegion> for IntegerRegion` and `From<IntegerRegion> for XnRegion` (already partially done — IntegerRegion wraps XnRegion)
2. Add convenience methods on `Edition` that return `IntegerRegion` instead of `XnRegion`
3. Gradually migrate `server.rs` and `otree_crdt.rs` to use trait objects
4. Keep `XnRegion` as the storage format; `IntegerRegion` as the API format

**Unlocks:**
- All space algebra operations available on edition regions
- Generic region queries (filter, intersect, delta, complement)
- Position-space polymorphism (Integer, Sequence/tumbler, Cross)
- Foundation for FilterSpace-based link queries

## Tier 2: Query and Decomposition

### 4. `simpleRegions` Steppers — Region Decomposition

**Current:** No way to iterate over the disjoint simple sub-regions of a complex region. Transclusion resolution (`transclusion.rs`) and diff hunk generation (`three_way.rs`) need this.

**With algebra:**
```rust
for simple_region in complex_region.simple_regions() {
    // Each simple_region is a contiguous [start, end] interval
    resolve_transclusion(simple_region);
}
```

**Unlocks:**
- Clean transclusion resolution across gaps (compound documents with multiple sources)
- Diff hunk generation (one hunk per simple region)
- Correct generic `count` (sum of simple region sizes)
- `compactor` on non-integer spaces

**Implementation:**
1. Add `Stepper` trait to `space/traits.rs`
2. Implement `simple_regions()` on `XnRegion` (transition list → contiguous intervals)
3. Add `Iterator` wrapper for Rust ergonomics
4. Use in `transclusion.rs` for resolution
5. Use in `three_way.rs` for hunk generation

### 5. Real Region-Based Filter — Link/Transclusion Queries

**Current** (`filter.rs`): Tag-based boolean algebra with `pass_joint` stubbed as no-op.

**Gold's Filter:** Matches actual regions. `Filter` is an `XnRegion` subclass that tests containment/intersection against a base region space.

**With real Filter:**
```rust
let query = FilterSpace::new(link_span_space)
    .filter(span_region.intersect(query_region));

// "Find all links whose span overlaps positions 100-200"
let matching_links = link_index.query(query);
```

**Unlocks:**
- Region-based backlink queries ("who links to this passage?")
- Transclusion overlap detection ("does this transclusion source overlap with my edit?")
- Connection panel filtering by text region
- Efficient link deletion when a span is removed
- Perspective view connection-line filtering by viewport

**Implementation:**
1. Complete `FilterSpace` to wrap a real `CoordinateSpace` instead of tags
2. Implement `Filter::matches(region)` using region intersection
3. Implement `Joint::pass(region)` for tree pruning
4. Build a `LinkIndex` that uses FilterSpace for region queries
5. Wire into `server.rs` backlink/link queries

### 6. `Dsp::minus` — Reversible Migration

**Current:** Once a span is migrated through an edit, the old mapping is lost. No way to "undo" a migration.

**With algebra:**
```rust
let edit_dsp = build_dsp(ops);
let undo_dsp = edit_dsp.minus(identity);  // or inverse for simple dsps
let original_span = migrated_span.transformed_by(undo_dsp);
```

**Unlocks:**
- Backfollow index re-resolution when edits are reverted (undo)
- Collaborative editing: undo a remote edit and restore old positions
- Version comparison: map positions between any two versions by composing Dsps
- Time-travel debugging for span migration

**Implementation:**
1. Add `minus` to `Dsp` trait
2. Implement for `IntegerDsp` (offset arithmetic)
3. Use in `backfollow.rs` for index maintenance
4. Use in CRDT for undo support

## Risks

| Risk | Mitigation |
|---|---|
| Connecting space↔edition is a large refactor | Do it incrementally — add bridge methods first, migrate callers one at a time |
| Performance regression from trait objects | Benchmark before/after; use generics (monomorphization) where hot |
| Existing tests depend on hand-written code | Keep old code as fallback during migration; add equivalence tests |
| `XnRegion` has features not in the trait (transitions) | Extend the trait or add extension methods |
