Access Guide

One server, four doors — every operation through the app, the CLI, an MCP agent, and the raw wire

Everything a Xudanu server can do is reachable four ways. Under all four sits the same WebSocket wire protocol and, below it, the same permission gates: a work you cannot read in the browser cannot be read by a script or an agent either. This page shows each common operation through each mechanism, with commands you can paste.

The examples are real. Every command on this page was executed against a running server (a public-sandbox demo and xudanu.com itself); outputs shown are actual outputs, trimmed for space.

2. Web app

The full human surface: the editor with inline link lanes and attribution, the right-hand Context panel (connections, docuverse map, presence), trails, compound builders, import. xudanu.com runs the production instance; demo.xudanu.com is a public sandbox needing no account.

For local development, ./scripts/restart.sh from the workspace root brings up the backend on :8080 and Vite on :5173.

Where transclusion lives in the UI: select text in a source work and the placement bar offers a live window; existing transclusions render inline with colour-coding and a badge showing their source. The Connections panel lists them per work.

3. Command line (xudanu-cli)

The scripting and operations surface. One-shot commands take <server-url> <command> [args...]; repl gives an interactive session.

xudanu-cli ws://127.0.0.1:8093 who-transcluded 1004
work 0x3ed (xudanu://work/1005) direct

The reuse graph in one line: work 0x3ed (1005) quotes work 1004, directly (not through an intermediate). Other commands: list-works, get-work, create-work, revise, create-link, find-content, grab/release, club-*, registry-*, info. Run bare for the list.

4. Agents (MCP)

xudanu-mcp speaks the Model Context Protocol on stdio and translates to the same wire ops — any MCP host (Claude Desktop, Cursor, OpenCode) becomes a docuverse researcher. Configuration lives in the MCP guide; the tool catalog arrives via the standard tools/list.

xudanu-mcp --server wss://xudanu.com

A minimal session over stdio (newline-delimited JSON-RPC):

{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"probe","version":"1.0"}}}
{"jsonrpc":"2.0","method":"notifications/initialized"}
{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"who_transcluded","arguments":{"work":1004}}}
{"reusers":[{"kind":"work","id":1005,"is_direct":true,"uri":"xudanu://work/1005"}],"total":1}

Reads need no flag. Writes are doubly gated — see section 6. Recipes for chaining tools (the reuse chain, citation pinning, provenance audits) ship as Agent Skills in the repository and as recipes embedded in tool descriptions; see the MCP guide's tool catalog.

5. Raw wire protocol

Everything above is a translation of this. Connect a WebSocket to /xudanu, send versioned JSON frames, await the matching id:

{"v":2,"type":"request","id":1,"op":"find_transcluders","payload":{"content_be_id":1004}}

The response carries the same triples the CLI and MCP reshape:

{"type":"response","id":1,"value":{"type":"transclusion_results","value":[
  {"element_type":"work","element_id":1005,"is_direct":true}]}}

Op names are snake-case wire ops (trail_list_published, work_license_get, server_directory_list, federated_search, 140+ more) — the full reference is the wire protocol page, regenerated from source by scripts/gen-wire-doc.py.

6. Writes and the gates

All four mechanisms pass the same server-side checks — ensure_can_read for reads, ensure_can_edit for writes — against the same club system. There is no door with weaker locks.

MechanismHow a write is authorized
Web applogin (identity or public sandbox policy); world-editable works on sandbox servers
CLIlogin / login-admin; the session carries your clubs
MCPoperator starts the bridge with --enable-agent-writes and every mutation still passes ensure_can_edit; in practice agents only touch world-editable works on public-sandbox servers
Wiresession authentication (tickets, OAuth, or public session); same gates
Agent attribution is structural. Everything an agent writes is signed as LLM-authored with its model identity in the provenance chain. It cannot claim to be you.

7. Honest gaps

Where the matrix says gap, the mechanism genuinely lacks the operation today:

  • CLI: no span reads with hashes, no trail walking, no license/provenance checks, no transclusion placement, no federated search. The highest-value candidates for a small CLI refresh.
  • Web app: federated search and the server directory are not surfaced; reuse connections exist per work but there is no corpus-wide reuse browser.
  • Agents: no delegated reads (an agent cannot read what only you can read, even when you ask it to) — read-delegation tokens are the designed answer, not yet built.

Gaps are tracked in the FR cards under docs/dev/; the follow-up list in FR-161's card is the current roadmap for this surface.
