The 1992 Link Model, Rendered

The Gold link model’s own components — bidirectional, multi-ended, gathered, described, contested — each one live, each one real.

What this is. An interactive gallery of the link machinery of Udanax Gold (the 1992 design, released 1999), rendered by Xudanu — the system that implements the Gold model today. Every component below is a working demonstration of a structure the model actually defines, exercised on the same corpus the live demo server uses. Nothing on this page is a mockup: every structure shown — multi-ended links, gathered end-sets, descriptors, comments-on-links — is stored by the same server that serves the live sandbox and the 1972 reading interface. This page is the deep end; corrections are welcome (below).
Why 1992, not 1999. The label is the design date, not the escape date. The Gold model existed as a design in 1992; the code escaped in 1999 as machine-generated C++ nobody could read; the shipped Windows frontend was 1993. This gallery renders the model, so it dates the model — the same convention the census and the complexity comparison already use.

Two doors

Nelson, describing where the design settled: “The Xanadu design has essentially resolved to one basic document concept: parallel pages with visible connections.” (hyperland.com). That is one sentence containing two interfaces, twenty years apart:

1972
parallel pages
the reading interface — the page, the panes, the trail. The ’72 skin, live on the sandbox.
1992
visible connections
the link model — end-sets, descriptors, the machinery that makes connections unbreakable and multi-ended. This page.

The doors are never mixed: the ’72 interface stays historically pure (that is its whole value), and the Gold components live here, dated 1992, in their own visual identity. But the two doors are not two systems. They are one server, one link store, two renderings — the ’72 client queries the same end-sets this gallery shows; it renders a reading subset of them. The gradient between the doors is deliberate: we built the Gold-capable interface first, watched it read as alien, and distilled the ’72 interface out of it. Readers who find this page confusing are supposed to — the ’72 door is the on-ramp, and this is the deep end.

Read this before judging the visuals. The Gold link UX was alien to its own decade. The 1993 frontend wrapped it in familiar professional chrome (insurance-rating forms) because the concepts had never met an audience they weren’t ahead of. The web later resolved the same tension by deleting the capability — one-way, one-ended, mute links — to stay legible. This gallery keeps the capability and labels the confusion instead. Each component carries a short caption saying exactly what the web dropped to buy its legibility. Alien-and-capable is the exhibit, not the defect.

The components

Corpus: the live demo server’s seeded link corpus — a quarterly claims report, a reviewer’s analysis, and field notes, connected the way a real dispute is connected. Every passage below is real seed text.

1. The two-ended link

The atom of the model: a connection between two passages that knows both its ends. Not a jump — an edge. It is visible from either end, carries a type, and survives edits to the text on either side (the span migrates; the link does not break). Hover either passage below; click to follow.

Q3 Claims Report
Customer escalations fell to their lowest level in three years, which we attribute to the new triage rota introduced in June.
Reviewer Analysis↩ 1 in
Escalations fell during a period when the intake form was broken — the funnel was narrower, not the sentiment better.
disagreement · link · 2 ends
LeftEnd“Customer escalations fell to their lowest level in three years” — Q3 Claims Report
RightEnd“the funnel was narrower, not the sentiment better” — Reviewer Analysis
The glyph on the far panel (↩ 1 in) is the backlink: the destination knows it is pointed at, without asking anyone. Clicking either passage follows the link to the other end.
What the web dropped. A web link is one-way and one-ended: the destination never learns it exists, backlinks are someone else’s crawler, and the moment the destination moves or dies, the link is silently broken. The Gold link is an edge in a graph both ends can see.
Gold model: canonical constructor builds exactly LinkTypes + LeftEnd + RightEnd (nlinksx.cxx:193) · our impl: links.rs HyperLink with two named ends; span migration on every edit · rendering: typed underlines are original — no colored underlines survive in the Gold sources; the beam card mirrors the ’72 client’s real link inspector

2. The three-ended link

A link has as many named ends as it needs. Three documents meet here — the report’s methodology, the reviewer’s rebuttal, and a field note nobody asked for — and the comparison itself is one object, not a pile of pairwise pointers. Hover any passage; all three ends light together.

Q3 Claims Report
We measured consecutive four-week windows and excluded the holiday gap, which we believe overstates the baseline.
Reviewer Analysis
The retiming coincided with the seasonal traffic trough; a year-over-year comparison, not four-week windows, is the honest measure.
Field Notes Q3
Corridor signage was replaced during the retiming window — a confounder nobody has mentioned in either document.
link 4C2 · comment · 3 ends
LeftEnd   report    “consecutive four-week windows and excluded the holiday gap”
RightEnd  analysis  “a year-over-year comparison, not four-week windows, is the honest measure”
ThirdEnd  notes    “Corridor signage was replaced during the retiming window”
The ledger is the link as stored: an edition whose named ends are references. Any number of names is allowed — three is just where it starts to be interesting.
What the web dropped. A web link has exactly two addresses. Any comparison of three sources becomes a listicle, a screenshot, or nothing at all — the comparison never gets to be a thing with its own identity, type, and history.
Gold model: a link-edition carries any number of named ends (nlinksx.cxx:102); Green’s from/to/three-set is this same shape with three names · our impl: links.rs end map — extra ends land as named end-set attachments (FR-40) · rendering: original; three-way demos live in the seeded Links Course on the sandbox

3. The gathered end-set

The centerpiece. One end of a link can be an entire set of passages — gathered. Here a single disagreement holds three separate claims from the report, each with its own ordinal, against one rebuttal. The end is not a list of links; it is one end, and it is a set. Hover the rebuttal — all three gathered passages light at once.

Q3 Claims ReportLeftEnd · 3 members
The western corridor throughput improved by forty percent1/3 following the signal retiming, and no incident metrics rose2/3 during the period. Maintenance costs per corridor-mile dropped twelve percent3/3 under the revised vendor contracts.
Reviewer Analysis
The retiming coincided with the seasonal traffic trough; a year-over-year comparison, not four-week windows, is the honest measure.
link 3A7 · disagreement · 2 ends, LeftEnd is a set
LeftEnd   report    { 3 members — a set, identity-keyed, unordered }
RightEnd  analysis  “a year-over-year comparison, not four-week windows, is the honest measure”
This is how a rebuttal actually argues: against a body of claims, not one sentence. The ordinals (1/3, 2/3, 3/3) are how the live editor shows a passage’s position inside a gathered end.
What the web dropped. Quote three passages in one comment and the three quotations have nothing to do with each other — three separate boxes, no set, no ordinal, no single thing to answer or to follow. On the web, a gathered disagreement is impossible to state.
Gold model: FeMultiRef — an end-set in IDSpace, a true set, identity-keyed, and nestable (a set of sets; nlinksx.cxx:479) · our impl: links.rs end maps of Vec<HyperRef>; the ’72 client’s gatherInto authors these sets from the reading surface · rendering: ordinals and the double underline are original; the “3 members” ledger is what the server stores

4. The descriptor

The link can speak in its own voice. Not the type, not the excerpt at the far end — its own sentence, stored as a named end of the link itself. The 1993 frontend invented exactly this: FELink:Descriptor, a human-readable description carried by the link, with a defined fallback chain. Step through the chain below.

Q3 Claims Report
The western corridor throughput improved by forty percent following the signal retiming.
Reviewer Analysis
The retiming coincided with the seasonal traffic trough.
1 · descriptor end → 2 · other-end excerpt → 3 · default the resolution order winfe shipped, 1993
the honest pairing
Tier 1 — the descriptor end: the link’s own words, stored as a named end. Hover either passage above to see what it describes.
What the web dropped. The web link is mute. Its title attribute, at best, is a tooltip for whoever happens to hover — it travels with the anchor, not the connection, and the destination never sees it. A connection that can explain itself does not exist on the web.
Gold model: FELink:Descriptor named end (winfe links.cpp:26); resolution: descriptor → other-end excerpt → “< New Link >” (links.cpp:73–77) · our impl: named ends on every link (link_add_end); descriptor boxes with collision-free placement (FR-40 Appendix B) · rendering: the gold box above is ours; the fallback chain and its order are winfe’s, exactly

5. Comment-on-link

Links are works — so a link can be the subject of another link. Not the text, the connection: a third reader can contest the dispute itself. This needs no special mechanism in the model; it falls out of everything-is-a-work. The inspector below sits open, as the live client leaves it — the link’s two ends, and what is attached to the link itself. Click either underlined passage to trace its end in the inspector.

Q3 Claims Report
We measured consecutive four-week windows and excluded the holiday gap, which we believe overstates the baseline.
Reviewer Analysis
The retiming coincided with the seasonal traffic trough; a year-over-year comparison, not four-week windows, is the honest measure.
comment · link 4C2 · 3 ends
LeftEnd“consecutive four-week windows and excluded the holiday gap” — Q3 Claims Report
RightEnd“a year-over-year comparison, not four-week windows, is the honest measure” — Reviewer Analysis
attached to this link — comment-on-link
“the whole dispute turns on measurement windows — four-week versus year-over-year. Settle that and both documents collapse into agreement.” — a note ending at link 4C2
The purple row is a second link whose end is not a passage but the first link. The subject of the comment is the connection itself. In the live ’72 client, clicking a marked passage opens this inspector for that link — the click-to-trace behavior above is the same gesture.
What the web dropped. You can comment on a page. You can never comment on a link — the connection is not an addressable thing, so it cannot be praised, disputed, or corrected. On the web, the argument about the argument has nowhere to live.
Gold model: a ref’s workContext may point at any work, including a link work — links-to-links for free (gold-link-model.md §1); winfe’s attachLink commented by linking to a fresh document (links.cpp:305) · our impl: link-attachment refs; the ’72 client’s inspector lists them under the link · rendering: the inspector above mirrors that real panel; the comment text is the live corpus’s own

6. The density pill

What happens when a passage is that connected — six connections stacked on one sentence? The Gold answer is not to hide the density; it is to make it visible at a glance and unfoldable. At five overlapping connections the cluster collapses into a single pill. Click it.

Q3 Claims Report · claim one
The western corridor throughput improved by forty percent following the signal retiming, and no incident metrics rose during the period.
The western corridor throughput improved by forty percent following the signal retiming, and no incident metrics rose during the period.
each bar is one connection · its width is the words it connects · its row keeps overlapping connections apart · hover to light its words in the sentence
hover a lane to read the connection — hovering also solos it (the live system dims the rest to 22%)
Collapsed: the pill is the count, not the clutter. Click it to unfold the itemized view — every connection becomes a bar: width is the words it connects, row keeps overlaps apart, color is type. Hover a bar to light its exact words in the sentence and solo it. In the live editor this is how a dense passage stays readable: fold it while passing through, unfold it when you care.
What the web dropped. The web has no indicator at all. A passage can be quoted, contested, and annotated forty times across the network and look exactly like a passage quoted zero times. Density of connection — arguably the most honest signal a document can emit — is simply invisible.
Gold model: none — density rendering is an application concern, honestly ours · our impl: threshold 5, interval-partitioned lanes, same-span clustering, focus-dimming at 0.22 (link-markers.ts, FR-4.5/FR-40) · rendering: original, and the lane assignment in this demo runs the real greedy partition on the real character offsets

What the web dropped. Web link creation is typing an href — the author states an address, never a claim, never a set, never a description. There is nothing to guide, because there is nothing to decide: the web’s link has no room for intent.

8. Trails

The one component simple enough to survive both eras. A trail is a curated path through the docuverse — stops, in order, each a passage. Gold’s shipped link list window was literally “the manager for a list of links and its trail” (winfe links.cpp:1); the ’72 interface renders the same concept as a reading path. Step through this one.

trail · “Reading Q3 critically” · 4 stops
What the web kept — almost. The web’s nearest survivor is the reading list: a frozen, one-way, author-only pile of URLs. A trail is a live ordering of passages that follows its text through edits, is followable by anyone, and can be annotated by anyone who walks it. Close, and nowhere near.
Gold model: trails as the link list window’s own concept (links.cpp:1); Nelson’s trails from the ’70s design · our impl: trails panel in both clients; the ’72 tour on the sandbox is a trail · rendering: deliberately in the ’72 form — the one component that needs no Gold-era costume

9. What the web dropped

The exhibit’s thesis, one row per component. Thirty years of UX discipline spent removing power to reduce confusion — the web resolved the capability-confusion trade by deleting the capability:

Structure (1992 model)The web’s nearest equivalentWhat is missing
Two-ended linka hrefThe destination never knows; backlinks are a third party’s crawler; edits break the link silently
Three-ended linklisticle, screenshotA comparison of N sources is never itself an addressable object
Gathered end-setN separate commentsThe set of claims vs one rebuttal cannot be stated as one connection
Descriptortitle tooltipThe link cannot carry its own meaning; the far end never sees it
Comment-on-linkcomment on a pageThe connection itself cannot be contested — only its endpoints
Density pill & lanesnothingConnection density is invisible; the most honest signal a document can emit does not exist
Guided creationtyping an hrefThe author states an address, never a claim — no room for intent
Trailsreading listFrozen, one-way, author-only; does not follow its text through edits
The trade, stated once. The web chose legibility and lost the connections. This page is what keeping the connections looks like.

10. One model, two doors

Worth saying precisely, because it is the page’s structural claim: the ’72 reading interface and this gallery are the same link model wearing two presentations. Not two models, not a bridge between them. The server holds one store of links — typed, multi-ended, gathered, described — and every client renders what it needs from it:

  • the ’72 client queries those links and walks every end, including gathered members, in its link inspector — and can gather new ends from the reading surface;
  • the modern workspace renders them as pills, lanes, clusters, and a guided creator;
  • this page renders the model’s full capability with the training wheels off.

The model implemented here is Xudanu’s — translated and extended from the released Udanax Gold source, and documented divergence-by-divergence (the concept doc, the complexity comparison). It is not Roger Gregory’s port, and it is not the 1999 code running; it is the 1992 design, implemented today, with its own honesty about what is original. The census keeps the field map; this page is the deep end of one entry in it.
