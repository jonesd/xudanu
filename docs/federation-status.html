1. Component status

FR-3 (federation activation) is implemented: passing --peer <addr> (repeatable) turns a server from a passive listener into an active federation node. The full design rationale is in the FR-3 spec; the operator walkthrough is Federation Activation.

3. The adversarial fault battery

scripts/federation-adversarial-tests.sh strikes a live 4-node docker cluster on seeded schedules. Every scenario must end sealed-or-halted-safely (no unsealed execution), every struck node must heal (docker unpause / restart), the cluster must converge to one sequence, the governance lifecycle must unify, and — the check that earned its keep — sealed-log digests must be identical on every node: no fork, no hole.

Latest result: 16/16 checks pass (seed 20261028) on the docker test bed. The same protocol changes are covered by in-process mesh tests (3,797 library tests green).

4. Two subtle bugs worth knowing

The dual-restart stall (liveness)

After two nodes restart simultaneously, a fresh propose could stall forever: the pre-prepare raced the leader’s re-established dials (one replica never received it) while the survivors’ reverse dials sat in reconnect backoff (their votes never reached the leader). Every node was below quorum, nothing was rejected, no timeout fired the view change. Fix: the transport replays the pending round — pre-prepare plus the node’s own signed votes — on every outbound (re)connect and on the periodic sync tick.

The catch-up race hole (safety)

A node killed shortly after boot loses its in-memory governance log (sealed batches persist only at checkpoint). State transfer restores what peers can send — but if the quorum seals a round while the node restarts, the node misses that broadcast. The view change that follows used to advance its sequence counter from the certificates’ highest_prepared: the counter said 6 while the log ended at 5. The next round then sealed over the gap, and no from_seq-based catch-up can ever fetch a middle hole. Fix (the textbook PBFT watermark rule): the watermark follows the log, never the certificates. Every guard that sees seals beyond the local log — NewView certificates, sealed-batch broadcasts, log-tail gaps — replies with a GovernanceLogRequest and the node backfills the missing batches in order through the certificate-verified tail path.

Why the no-fork digest check matters: node 3 reported sequence=7 like everyone else — the hole at position 6 was invisible to any counter-based health check. Only comparing full digest lists exposed it.
