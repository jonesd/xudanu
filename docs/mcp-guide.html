MCP Guide

Your docuverse as tools for LLM clients — read-only by standard configuration

xudanu-mcp is a Model Context Protocol server that lets an LLM client — Claude Desktop, Cursor, or any MCP host — search and read a Xudanu docuverse like a research assistant: full-text search, transclusion-resolved reading, backlinks, provenance, version comparison, live watching. The agent becomes a user like any other, with the same read gates as everyone else.

Standard configuration is read-only. The documented tools cannot modify anything. A write mode exists behind an explicit operator flag and is not covered by this guide; see the note at the end.

1. Quickstart

Three steps, no build, no account:

Step 1 — get the binary. Download xudanu-mcp for your platform from the releases page and make it executable:

curl -LO https://github.com/jonesd/xudanu/releases/latest/download/xudanu-v1.17.1-aarch64-macos.tar.gz
tar xzf xudanu-v1.17.1-aarch64-macos.tar.gz
chmod +x xudanu-mcp

Step 2 — point it at a server. Any Xudanu server works. Two public ones:

ServerURLPolicy
xudanu.comwss://xudanu.com/xudanuRead-only for visitors (hosted instance)
demo.xudanu.comwss://demo.xudanu.com/xudanuPublic sandbox, seeded demo corpus
Your ownws://127.0.0.1:8080/xudanuWhatever you configured

Step 3 — register it with your client (next section), then ask your agent something like:

Search the docuverse for "spectrum sentence" and read that work.
What connections touch it, and who wrote what?

2. Client configuration

Claude Desktop

Edit claude_desktop_config.json (Settings → Developer → Edit Config) and add:

{
  "mcpServers": {
    "xudanu": {
      "command": "/absolute/path/to/xudanu-mcp",
      "args": ["--server", "wss://xudanu.com/xudanu"]
    }
  }
}

Cursor

In .cursor/mcp.json (project) or the global MCP settings — same shape:

{
  "mcpServers": {
    "xudanu": {
      "command": "/absolute/path/to/xudanu-mcp",
      "args": ["--server", "wss://demo.xudanu.com/xudanu"]
    }
  }
}

Any other MCP host

Anything that speaks MCP over stdio: point it at the binary with the same arguments. Test a connection by hand before wiring it into a client:

printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"probe","version":"0"}}}' \
  | ./xudanu-mcp --server wss://xudanu.com/xudanu

A serverInfo response naming xudanu means you're connected. Diagnostics go to stderr; the protocol conversation goes to stdout.

TLS is required for remote servers. wss:// validates certificates against webpki roots — Let's Encrypt works, self-signed does not. Plain ws:// is for local servers.

3. The tools

ToolWhat it does
search_worksFull-text search across works the session can read, with context snippets and metadata
read_workA work's full text, transclusions resolved (windows show their live source content)
read_spanA specific span, optionally pinned to a revision; the returned excerpt is hash-stamped
verify_workVerify a previously returned span against its recorded hash — quotable with confidence
find_backlinksEvery connection pointing at a work — the both-ends property, from the agent's chair
who_transcludedWhich works reuse a passage, and where it came from
get_provAuthorship and lineage as W3C PROV-JSON
get_version_infoRevision count and timeline for a work
compare_versionsTwo revisions side by side, differences labeled
watch_workSubscribe to changes on a work (detector)
detector_events / detector_ack / unwatch_workRead, acknowledge, and retire watch events

4. Addressing: xudanu:// references

Tools that point at content use one canonical scheme:

xudanu://work/<id>                    the current edition of a work
xudanu://work/<id>?rev=<n>            a specific revision (pinned)
xudanu://work/<id>#span=<s>,<e>       a character range in the current edition
xudanu://work/<id>?rev=<n>#span=<s>,<e>  a range in a pinned revision

Because positions are tumblers — addresses, not offsets — pinned references survive edits elsewhere in the document, and hash verification catches any drift.

5. What agents can see

The MCP session is an anonymous session of the server, exactly like a first-time visitor in a browser:

  • Every read tool checks ensure_can_read before returning anything
  • Search skips unreadable works entirely — no titles, no snippets, no metadata leakage
  • Server secrets (keys, audit logs, configuration) are not part of the works layer and are unreachable through these tools
  • On origin-gated servers the connection itself is refused unless it presents the allowed origin

The operating rule is simple: published means public. An MCP client reads what any reader reads — nothing more.

6. The three risks, in plain language

Risk 1 — data-dir mode is a skeleton key

The binary also accepts a data directory instead of --server, opening the store directly with no logins and no rules. That mode is for offline analysis of a copy. Never point it at a live production data directory, and never with writes enabled — two writers on one store can corrupt it.

Use --server mode. It is the documented, recommended, and safest configuration; everything in this guide assumes it.

Risk 2 — documents can talk to the agent

An LLM cannot always tell content from instructions. A document in the corpus can contain text addressed to AI assistants ("ignore your instructions and…"). Even read-only, a poisoned corpus can make an agent report misleading summaries. Treat corpus text as untrusted input: verify quotes that matter (verify_work), and prefer host-side tool approval for anything sensitive.

Risk 3 — model identity is self-reported

The write mode stamps revisions with a declared model identity. That label is what the operator typed, not a verified fact. It is attribution metadata, not authentication — do not build trust on it.

7. Note on the write mode

An opt-in write mode exists (--enable-agent-writes): agents can create works, transclude, link, and revise, with every change stamped as LLM-authored in the provenance system and the chained audit log. It is additionally gated by the server's edit policy — an owner-only server refuses agent writes no matter what the client requests.

It is deliberately undocumented beyond this note. Guidance while it matures: enable it only against sandbox copies, never against data you care about, and never on a server you share with strangers.
