Xudanu User Guide

Version 0.7.0 — Stars, Trails, Document Map, Content Similarity, and hardened persistence

Xanadu Gold Foundations

Xudanu builds directly on the Udanax-Gold hypertext model — Ted Nelson's C++ implementation open-sourced in 1999 — with modern enhancements including BLAKE3 content hashing, Ed25519 cryptographic attribution, CRDT-based collaborative editing, and a real-time web UI. The features in this release rest on core Gold abstractions:

  • Works & Editions — Documents are Works containing versioned Editions. Each Edition captures a complete snapshot with per-line attribution, three-way merge, and the O-tree CRDT data model.
  • Transclusion — The foundational Xanadu concept: content is linked, not copied. When you transclude text from one document into another, provenance is preserved — the attribution panel shows via work:XXXX for every transcluded passage.
  • Content Addressing — Every piece of text has a BLAKE3 content hash. Identical content shares the same address, enabling automatic transclusion detection and deduplication across documents and revisions.
  • Clubs & Permissions — The Gold club hierarchy controls read/write access. Personal clubs own your edits; groups enable collaboration; the public club allows anonymous access.
  • Cryptographic Attribution — Every edit is signed with Ed25519. The attribution system traces every character back to its author, distinguishing human input, LLM-generated text, historical imports, and transcluded passages.
  • Trails — Ordered paths through documents, directly implementing Nelson's concept of guided reading sequences through a hypertext corpus.
  • Document Map — Visualization of the transclusion and similarity graph, showing how documents relate to each other across the entire corpus.

Quick Start

  1. Download the release for your platform from GitHub Releases
  2. Extract the archive: tar -xzf xudanu-v0.7.0-*.tar.gz
  3. Initialize a data directory: ./xudanu-server init ./data
  4. Start the server: ./xudanu-server run 127.0.0.1:8080 ./data --static-dir ./dist
  5. Open http://127.0.0.1:8080 in your browser
  6. Click Sign In and enter credentials (default admin password is set via ADMIN_PASSWORD env var)

Document Editing

Create documents from the sidebar. Click a document to open it in the editor. All edits are saved automatically — there is no Save button. Every keystroke is recorded as a CRDT operation with cryptographic attribution.

Attribution

Click the Attribution button (or use the More menu) to see who wrote each section of text. Attribution spans are color-coded:

■ Green — Human

Text typed directly by a logged-in user

■ Purple — LLM

Text generated by the AI assistant

■ Amber — Historical

Text from imported or source documents

■ Gray — Unattributed

Text with no provenance information

Transclusion

Select text in a document, then click the Transclude button that appears. Choose a target document. The selected text is copied into the target with full provenance tracking — the attribution panel will show via work:XXXX for transcluded passages.

Stars (Favorites)

Star documents to mark them as favorites. Starred documents appear in a dedicated Favorites section at the top of the sidebar, and are shown as amber circles in the Document Map.

How to star a document

  • Open a document and click the ★ star icon in the header bar
  • Or hover over a document in the sidebar and click the star icon
Tip: Stars are saved immediately and survive server restarts. They are persisted via the WAL (Write-Ahead Log) and included in every checkpoint.

Trails

Trails are ordered sequences of documents — curated reading paths through your hypertext corpus. Each trail has a name and an ordered list of stops (documents).

Creating a trail

  1. Open the More ▾ menu and select Trails
  2. Type a name in the "New trail name..." field and click Create

Adding documents to a trail

  1. Open the document you want to add (click it in the sidebar)
  2. Open the Trails panel (More ▾ → Trails)
  3. Click the + button on the trail card

Managing trail stops

  • Reorder: Use the ▲ / ▼ arrows to move stops up or down
  • Remove: Click the × button on a stop
  • Navigate: Click a stop's title to open that document
  • Delete trail: Click the × button on the trail card header
Tip: All trail operations auto-save immediately. There is no Save button — every add, remove, and reorder is persisted via WAL and checkpointed.

Document Map

The Document Map is a force-directed graph visualization showing all readable documents and their relationships.

Opening the map

Open the More ▾ menu and select Document Map.

What you see

● Blue nodes

The currently open document

● Amber nodes

Starred documents or source (imported) works

● Gray nodes

Regular documents

Node size

Current doc is largest, starred/source medium, regular smallest

Connections

  • Solid lines with arrows — Transclusion links. Documents that transclude content from each other are connected. These pull together with strong force.
  • Dashed lines — Content similarity. Documents that share significant word overlap (>15% Jaccard similarity) are connected. These pull together with weaker force, so similar documents drift nearby without clustering as tightly as transcluded documents.

Interactions

  • Click a node to navigate to that document (closes the map)
  • Drag a node to rearrange the layout
  • The physics simulation runs for 300 frames on load
Tip: Documents that share vocabulary naturally cluster together. If you see a tight cluster of dashed lines, those documents cover similar topics and may benefit from being organized into a Trail.

Revisions

Every edit creates a new revision. Open the More ▾ menu and select Revisions to browse the history. You can compare any two revisions side by side.

Compare

Select two documents and open More ▾ → Compare to see a side-by-side diff with attribution coloring. Requires at least 2 documents to exist.

Persistence

v0.7.0 includes a hardened persistence layer with three layers of protection:

  1. WAL (Write-Ahead Log) — Every star, trail, and manifest mutation is appended to wal.log before the operation completes. On restart, the WAL is replayed to recover any operations that happened after the last checkpoint.
  2. Dual Manifest — The manifest is written to alternating slots (manifest_a.json / manifest_b.json) before being renamed to manifest.json. If the primary is corrupt, the server falls back to the higher-sequence backup slot.
  3. Atomic Checkpoints — Manifest writes use the tmp+fsync+rename pattern for crash safety. Auto-checkpoint runs every 5 seconds when changes are pending.
Note: If you upgrade from a previous version, delete old data and re-initialize: rm -rf data/manifest*.json data/chunks/* then ./xudanu-server init data. The manifest schema has changed.

Keyboard Shortcuts

Ctrl+S Force checkpoint (no-op in browser, handled by server)
Ctrl+K Open command bar
Ctrl+/ Search within document

CLI Reference

./xudanu-server init <data-dir> — Initialize a new data directory
./xudanu-server run <addr> <data-dir> [options] — Start the server
./xudanu-server preflight <data-dir> — Validate data integrity

Options for run:
--static-dir <path> — Serve static files from directory (the web UI)
--csrf-token — Enable CSRF token validation
--admin-password <pw> — Set admin password (min 10 chars)
ADMIN_PASSWORD — Env var alternative for admin password
